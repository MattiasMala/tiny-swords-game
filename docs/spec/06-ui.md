## 0. Architecture of the current UI (what to reproduce, what is free to change)

* The UI is **immediate mode**, redrawn every frame on a single Canvas 2D (`render()` main.js:436-457). Every
  widget call both draws and returns its interaction state. All UI state lives in the `UI` object (ui.js:29-112),
  `Menu` (ui.js:556), `Ctl` (control.js:80) and a few `G` fields. **None of it is simulation state.**
* The UI only *reads* simulation data (resources, rates, units, queues, points, techs…) and *writes* through
  `command(cmd, ...args)` (factions.js:425): in solo it calls `execCommand(G.player, …)` immediately and returns a
  refusal reason string (or `null`); as a network client it sends `{t:'c', c, a}` to the host and returns `null`
  (the host later sends the reason back as a `toast` event). The Rust port must keep this: UI → `Command` enum →
  sim; refusal reasons come back as an event that the UI shows as a toast.
* Exception (must be fixed in the port): the **Modalità test** screen mutates sim state directly
  (`f.res[k] += 1000`, `G.frozen`, `Fog.on`) — see §10.8. In Rust this must become a solo-only debug command.
* Coordinates are **physical pixels** (canvas = window × devicePixelRatio × Quality scale). Every size is
  multiplied by a UI scale `s` (see §1). The bevy_ui port should reproduce the layout with absolutely positioned
  nodes (or a custom immediate-mode layer) using the same formulas; numbers below are in "design units" (multiply by `s`).
* Font: **Fredoka**, weight 600 (`fonts/Fredoka.ttf`, fallback "Trebuchet MS", Verdana, "DejaVu Sans", sans-serif)
  (assets.js:8-9). Sizes are pixel sizes (`600 ${round(size)}px`).

### 0.1 Text primitive `label(ctx, str, x, y, size, color='#fff', align='left', outline='#1b1f33')` (assets.js:495)
* `textBaseline = 'middle'` → `y` is the vertical **center** of the text. `align` ∈ left / center / right refers to `x`.
* If `outline` is not null: stroke first with `outline` color, `lineWidth = max(2, size/5)`, `lineJoin='round'`, then fill.
* Calls in this spec marked **(no outline)** pass `null` → plain filled text (used on parchment). Calls without that
  mark use the default dark outline `#1b1f33` (used on dark backgrounds / over the world).
* `wrapText(ctx, str, width, size)` (ui.js:115): greedy word wrap on single spaces, measuring with the same font.

## 1. UI scale

* `G.us` (HUD scale, main.js:150-152): `fit = min(W/1500, H/850)`; `G.us = clamp(fit, 0.72*dpr, 1.5*dpr)` where
  `W,H` = canvas physical size and `dpr = W / window.innerWidth`. All HUD widgets (top bar, selection panel,
  minimap, shortcuts, hints, tooltips, cursor) use `s = G.us`.
* Menu: `s = min(W/980, H/760, 1.35*dpr)` (ui.js:594).
* Management screens (`manageFrame`): `s = min(W/(w0+40), H/(h0+70), 1.3*dpr)` (panels.js:47) — independent of `G.us`.
  **Tooltips inside management screens are still drawn at `G.us`** (panels.js:409).
* Help: `s = min(W/980, H/(h0+20), 1.3*dpr)` with `h0 = 132 + 12*32 + 7*28 = 712` (ui.js:501-502).
* Pause & game over: `s = min(W/900, H/640, 1.3*dpr)` (ui.js:517, 531).
* Cursor: `s = max(dpr, G.us)` (ui.js:656).
* Loading screen uses `d = dpr` (main.js:421-434).

### 2.3 9-slice panels (`PANEL`, assets.js:445-467)
The sheets have **gaps between cells**, so slices are given as `[srcX, srcW]` triples:
* `G3 = [[0,64],[128,64],[256,64]]` — 320 px sheets (corner 64, center 64, corner 64; 64-px transparent gaps).
* `G7 = [[0,128],[192,64],[320,128]]` — 448 px sheets (corner 128, center 64, corner 128).
* `G1 = [[0,64],[64,64],[128,64]]` — 192 px contiguous sheets.
Same arrays for x and y. Corners are drawn at `slice*s`; edges and center are **stretched** (not tiled). If
`left+right > w` (or `top+bottom > h`) corners are shrunk proportionally (`nineSlice`, assets.js:431).

`drawPanel(def, x, y, w, h, s)`: `(x,y,w,h)` is the **visible** rectangle; the image is drawn at
`(x - padL*s, y - padT*s, w + (padL+padR)*s, h + (padT+padB)*s)` with corner scale `s`.

## 3. UI core: hit testing, hot state, keyboard navigation (ui.js:29-112)

### 3.1 State (`UI`)
| field | meaning |
|---|---|
| `hot` / `_hot` | mouse is over some UI this frame (`_hot` accumulates; `end()` copies to `hot`). `Ctl.update` (which runs in `update()` *before* render) uses last frame's `hot` to block world clicks / wheel zoom. |
| `locked` | when true, `over()` returns false and hits are not registered (HUD drawn under a modal). |
| `cursor` | 'arrow' (default) / 'hand' / 'no' / 'attack' / 'axe' / 'pick' / 'knife' / 'hammer' |
| `tip` | tooltip descriptor `{x, y, below?, title, key?, desc, cost?, lock?}` or null |
| `help` | help overlay open |
| `mapDrag` | dragging the minimap |
| `panel` | open management screen: `'units' | 'workers' | 'tree' | 'build' | 'market' | 'send' | 'test'` or null |
| `fresh` | panel just opened: the opening click must not count as "click outside" |
| `marks` | Set of unit ids checked in the Unità screen |
| `slide` | resource key whose slider is being dragged (Lavoratori) |
| `sent` | `{k, v, t}` last value sent by a slider (dedupe) |
| `send` | Invia state `{ids, x, y, kbd, go}` |
| `kbd` | keyboard drives the focus highlight (until the mouse moves > 2 px, main.js:180) |
| `focus` | point `{x,y}` (screen) inside the focused button |
| `focusRect` | rect of the focused button this frame (for drawing) |
| `rects`, `last` | button rects registered this frame / previous frame |
| `nav` | pending arrow `[dx,dy]` applied at next `begin()` |
| `enter` | Enter/Space pressed this frame while `kbd` |

### 3.2 Functions
* `open(name)`: toggle — `panel = (panel === name) ? null : name`; `fresh = true; slide = null; focus = null;
  marks.clear(); G.placing = null; Ctl.mode = null`.
* `begin()` (start of render): `_hot=false; cursor='arrow'; tip=null; locked=false; last=rects; rects=[]; focusRect=null;`
  if `nav` pending → `step(nav)`, `nav=null`.
* `end()`: `hot = _hot; enter = false`.
* `over(x,y,w,h)`: `!locked && mouse inside [x, x+w) × [y, y+h)`.
* `area(x,y,w,h)`: if over → `_hot = true` (blocks world input under panels without being a button).
* `hit(x,y,w,h)` → `{hover, down, clicked}`:
  * if `kbd`: `hover = !locked && focus inside rect` (and then `focusRect = rect`); else `hover = over(rect)`.
  * if `!locked`: push rect to `rects` (so it is keyboard-navigable next frame).
  * hover → `_hot = true; cursor = 'hand'`.
  * `down = hover && !kbd && Input.lmb`; `clicked = hover && (kbd ? enter : Input.pressed)` (press = mouse-down edge).
* `navigate(dx,dy)` (arrow while modal): if `panel === 'send'` and `send` exists → move target point:
  `send.kbd = true; send.x = clamp(send.x + dx*TILE*3, 0, World.W*TILE)`, same for y (TILE = 64 → 192 px/step).
  Else `kbd = true; nav = [dx,dy]`.
* `press()` (Enter/Space while modal): if Invia with `send.kbd` → `send.go = true`; else if `kbd && focus` → `enter = true`.
* `step(dx,dy)` (focus movement, pseudo-code):
  ```
  all = last (rects of previous frame); if empty return
  mid(r) = center of r
  cur = rect in all that contains focus (if focus)
  best = none, bd = ∞
  for r in all:
    (x,y) = mid(r)
    if cur is none: d = hypot(x - W/2, y - H/2)            // first press: button nearest screen center
    else:
      (x0,y0) = mid(cur)
      along  = (x-x0)*dx + (y-y0)*dy
      across = |(x-x0)*dy| + |(y-y0)*dx|
      if r == cur or along < 4 or across > along*2: continue
      d = along + across*1.5
    if d < bd: bd = d; best = r
  if best: focus = mid(best)
  ```
* `drawFocus()` (after all modals): if `kbd && focusRect`: brackets at `(r.x-5, r.y-5, r.w+10, r.h+10)` with
  scale `clamp(min(r.w, r.h)/70, 0.45, 1)` (pixels, not multiplied by s).

### 3.3 Frame order (main.js:436-457) — reproduce as UI layer z-order
1. `UI.begin()`; world render.
2. If `G.state === 'menu'`: `drawMenu` (demo battle runs behind it).
3. Else: `UI.locked = paused || help || state==='over' || !!panel`; `drawSpectator` if `G.spectate` else `drawHUD`;
   `UI.locked = false`; `Ctl.drawScreen` (drag-select rectangle); then exactly one of: `drawGameOver` (state 'over') /
   `drawPause` (paused) / `drawManage` (panel open and not spectating).
4. If `UI.help`: `locked=false; drawHelp`.
5. `UI.drawFocus`; `UI.end()`; `drawCursor`.
6. After the frame: `Input.pressed/released/rpressed/moved = false; wheel = 0` (main.js:475).

### 3.4 Input routing (main.js:221-274) — key table relevant to UI
`NAV`: ArrowLeft/KeyA = (-1,0), ArrowRight/KeyD = (1,0), ArrowUp/KeyW = (0,-1), ArrowDown/KeyS = (0,1).
`modal = state==='menu' || state==='over' || paused || UI.help || !!UI.panel`.
* `handleNav`: if not modal → `UI.kbd = false`. Each nav key press (including repeats): modal → `UI.navigate`;
  else if placing a building / pickmove (and playing, not spectating, no result) → `Ctl.keyMove`. Enter/NumpadEnter/Space
  (non-repeat): modal → `UI.press()`; placing → `Ctl.keyConfirm()`.
* `handleKeys` (non-repeat presses, in order):
  * `KeyM` → toggle audio; `F1` → toggle help; `F2` → lights cycle; `F3` → resolution cycle (always).
  * if `state !== 'play' || G.result`: only `Escape` closes help; stop.

## 16. Porting notes and open questions

* **Q1 (probable bug):** HUD help button (§6.1) sets `UI.help = true` during `drawHUD`; `drawHelp` runs later in the same frame
  while `Input.pressed` is still true and the mouse (top-right) is usually outside the help panel → the panel closes immediately.
  F1 works. Menu help button is inside the help panel area so it works. Recommendation: apply the `fresh` guard to the help overlay too.
* **Q2:** Double click sound: `tinyButton` already plays `click`, and callers (`drawActions` → `Ctl.act`, Unità train → `say`)
  play `click`/`deny` again. Decide whether to keep.
* **Q3:** Tooltips in management screens are drawn at `G.us` while the screen uses its own `s`; HUD tooltips use `G.us`. Keep or unify.
* **Q4:** `Ctl.groups` comment says "Ctrl + numero" but code/help use **Shift** + digit to assign. Follow the code/help.
* **Q5:** Unità screen "Ferma" acts on all marked units (pawns included) although it sits under "Truppe spuntate".
* **Q6:** The `Sposta` context action has no `code` (V is handled only by the global shortcut, which is ignored while a panel is open);
  `Canc` maps to code `Delete`.
* **Q7:** Minimap assumes the world aspect equals 270:180 (3:2) because one `k` is used for both axes. If the new aesthetic map
  generator changes the size/aspect, compute `ky = mh/(World.H*TILE)` or size `mh` from the aspect (Invia already does).
* **Q8:** `drawGroupInfo` hp strip is not clamped (hp > maxHp would overflow); `hpStrip` is clamped. Clamp in the port.
* **Q9:** Closing Invia via X / outside click leaves `UI.send` set (harmless; it is overwritten on next Invia).
* **Q10:** Era/clock banner uses a sword sprite (`Swords.png`) with empty text; the era label and clock are separate labels.
* **Q11:** Modalità test writes sim state from the UI — must become solo-only debug commands in the deterministic Rust sim.
* **Q12:** F2/F3 help lines describe Canvas lighting/resolution toggles; map them to Bevy quality presets (e.g. post-processing
  levels / render scale) so the existing Italian strings remain accurate.
* **Q13 (new requirement):** reconnect after page reload. The lobby/HUD will need an extra state (e.g. "rejoin") and the
  `playerLeft` banner (`…il giocatore è uscito, ora lo guida l'IA`) should be followed by a "player returned" banner; new strings
  are not in the JS and must be authored in the same style.
* Rendering vs sim: everything in this document is client-side presentation. The only sim-coupled values are listed in §15; the
  Rust UI should consume them from the local sim (solo) or the replicated snapshot (network) through the same read-only view.
* bevy_ui implementation hints: absolute-positioned `Node`s recomputed on window resize with the scale formulas of §1; nearest
  sampling for all UI textures; custom 9-slice for gapped sheets (§2.3); text with outline needs a shader/duplicate-text trick
  (Bevy has no built-in stroke) — e.g. 8-direction offset copies in `#1b1f33` at `max(2, size/5)` px, or an SDF font material;
  keyboard focus navigation can reuse the geometric algorithm of §3.2 over the frame's interactive node rects.
